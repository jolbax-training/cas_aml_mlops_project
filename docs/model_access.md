# Model access and spending ledger (offline-tested; paid smoke passed 2026-11-03)

Code: `openrouter_config.py`, `openrouter_client.py`, `ledger.py`, `openrouter_cli.py`; versioned config `src/codegen_eval/model_configs/openrouter_glm_v1.json` (hash recorded in each bundle's `identity.model`). Everything is tested with a fake transport offline. The paid smoke has run (2026-11-01 and 2026-11-03): the forced smoke `20261103T050806Z-30949f` reached the final-only call, calibration passed with the bound at about 2x the reported prompt tokens (decision: keep 2.0), and the settings freeze was written. Provider OpenInference matched the pin on every attempt, but the provider returns no precision field, so precision is pinned by the provider tag only. Evidence: [smoke_evidence.md](smoke_evidence.md).

- **Pinning:** `z-ai/glm-5.3-flash`, provider `open-inference/fp4` (order + only), fallbacks off, require-parameters on, temperature 0.2, top-p 1, reasoning `low`, 2,000 output / 12,000 input tokens, 60 s per attempt. The final-only call sends `tool_choice: none` and resends the tool definitions so history stays valid on the wire (the forced smoke's fourth call succeeded with require-parameters on; the wire payload is not stored in the bundle).
- **Pre-send check:** estimate = ASCII characters of the serialized request / `input_bound_ascii_chars_per_token` (default 2.0, in the config hash) + one token per non-ASCII byte + 8 per message; over 12,000 is rejected before reservation or sending (`request_rejected`). English and code run at roughly 3-4 characters per token, so 2.0 carries a margin of about 1.5-2x, and JSON escapes and sampling fields over-count further. No GLM tokenizer is available offline; the 2026-11-03 smoke observed ratios of 2.05-2.10 against reported prompt tokens. The provable byte bound (ratio 1.0) rejected realistic fourth calls (about 3 KB of code per round), which would bias the comparison, so it is not the default. **Gate (task 4.4):** the smoke test records `input_token_bound` and reported `prompt_tokens` per attempt (`bound_to_prompt_tokens`, printed by the smoke command); the bound must be shown to stay at or above the actual count (ratio at least 1, with margin) or be changed, and the decision recorded in `docs/progress.md`, before any main run.
- **Retries:** timeouts, connection errors, HTTP 408/429/5xx (and such codes inside a 200 body); one per request, two per trial, backoff 1 s for the trial's first retry and 2 s for its second (Retry-After honoured, capped 10 s). Refusals, malformed or truncated output, 4xx are never retried. No SDK is used.
- **Ledger:** append-only JSON lines outside Git, default `~/.codegen_eval/spend_ledger.jsonl` (override `CODEGEN_EVAL_LEDGER` or `--ledger`). Reservation is fsynced before each send; checkpoint (CHF 10) and ceiling (CHF 15) use committed + reservations. Uncertain charges (timeout, error, missing usage) keep their reservation. Inputs: a pricing file (`docs/openrouter_pricing.example.json`; fx, margin and fees must be filled and rechecked).
- **Attempt records:** each physical attempt is stored in the trial record (`attempts`, `reservation`, `latency_ms`, `errors`) and the incremental call log; missing fields are listed in `missing_fields`; no credential is stored.
- **Reproducibility limit:** a fixed model identifier does not guarantee immutable upstream weights; returned model/provider are recorded per attempt.

Smoke command (spends money; refuses without both):

    export OPENROUTER_API_KEY=...
    .venv/bin/python -m codegen_eval.openrouter_cli smoke --pricing ~/prices.json --i-accept-cost

Unforced smokes usually submit after 2-3 calls and never reach the final-only call, which the calibration gate requires. `smoke --exercise-final-only` (smoke only; `experiment_cli` has no such option) appends a fixed instruction, recorded with its hash in `identity.smoke`, telling the model it has three `run_checks` attempts, must use all three (one call per message) and must answer only after the third result, when tools are disabled. Nothing else changes: model config and `config_hash`, system prompt, agent limits and controller are as before, and the fourth request is built by the normal controller (full history, `tool_choice: none`, tools resent). The model may still submit early; the trace is then retained and calibration still fails. The freeze record notes the smoke mode (`standard` or `exercise_final_only`), and the retained trace is of a prompted fourth call, an exception to "only instruction, signature and versioned prompt" that applies to the smoke only.
