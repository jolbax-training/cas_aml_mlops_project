# Proposal

## Why

The first comparison (`prompt_comparison_v1`: `baseline_agent_v1` against `baseline_agent_v2`, ten tasks x 3 trials, 27/30 -> 29/30) is too small to say anything about run-to-run variation, and its fixed order (baseline, then revised hours later) cannot separate provider drift from the prompt. The user approved a second, larger comparison, presented as "the pipeline at scale" and not as proof of improvement, to enrich the presentation with a measured spread.

## What Changes

- A new experiment `prompt_comparison_v2`: the same frozen settings, model configuration, benchmark, prompts (`baseline_agent_v1`, `baseline_agent_v2`), agent and execution limits and container image as v1, with 10 trials per task (100 per run) and three runs in the order A-B-A: baseline, revised, baseline repeat (about 300 trials).
- Small, default-preserving tooling changes so the experiment tooling can describe it: `build-config` gains `--experiment-id` and `--trials-per-task` (defaults are v1's), the drift check rebuilds with the recorded values, `run` gains `--experiment` (MLflow experiment name, default unchanged), and the config, settings-freeze and probe writers refuse to overwrite any existing file whose content would differ.
- A deterministic, offline analysis command (`codegen_eval.scale_analysis`) that reads the retained bundles and reports, per run, the v1 metrics plus per-task successes out of 10, a Wilson 95% interval for the overall success rate and the charged CHF (for the stop rule), then baseline vs revised and baseline vs baseline-repeat.
- A one-page backup slide for questions, with the conclusions of the second experiment and its comparison with the first, framed "small samples mislead" (user decision). It is generated by a new `scripts/build_backup_slide.py` from committed evidence only, written to `backup_slide/backup_slide.html`, and does not touch `presentation/` or `report/` (design.md, Decisions 9 to 14).
- Separate storage for everything v2 writes: bundles in the primary checkout's `run_bundles_v2/` (already excluded locally through `.git/info/exclude`; no `.gitignore` change), evidence committed on the branch in `experiments/evidence_v2/`, MLflow experiment `codegen-eval-prompt-comparison-v2`. Nothing v1 is modified or deleted.
- New documents only: `experiments/prompt_comparison_v2.json`, `docs/prompt_comparison_v2.md`, `docs/comparison_evidence_v2.md`. The exact command sequence for the coordinator's three paid runs is fixed in `design.md` and `tasks.md`.
- Not in this change: the presentation and report (`presentation/*`, `report/*`, `scripts/presentation_evidence.py`); how v2 reaches them is a later change.

## Capabilities

(none)

### Modified Capabilities

## Impact

- Code: `src/codegen_eval/experiment.py` (parameterised `build_config`, drift check, overwrite guards), `src/codegen_eval/experiment_cli.py` (`build-config` and `run` options), new `src/codegen_eval/scale_analysis.py`; tests in `tests/test_experiment.py` (adapted), `tests/test_architecture_diagrams.py` (module list) and new `tests/test_scale_config.py` and `tests/test_scale_analysis.py`. Appended sections only, no existing text changed: `README.md`, `docs/demo.md`, `docs/work_log.toml`, `docs/progress.md`. Evaluator code changes, so a new probe record is needed for v2 (the v1 probe record is untouched).
- Backup slide (new files only): `scripts/build_backup_slide.py`, `backup_slide/` (page, user-text file), `experiments/evidence_v2/analysis/scale_analysis_v1.{json,txt}` (read-only extract of the v1 bundles), `tests/test_build_backup_slide.py`, one CI step. No `src/` change, so the recorded probes stay valid; nothing under `presentation/` or `report/` and none of the deck, report, evidence, chart or demo scripts changes.
- Data: only new files; v1 config, evidence, documents, bundles and the spend ledger are never written by this change (the paid commands append to the ledger through their normal budget path).
- Cost: paid runs by the coordinator only; projection in `design.md`.
- Milestone: extends the completed comparison phase (optional enrichment, beyond the 32-hour scope's required evidence); no dependency of any required deliverable on it.
