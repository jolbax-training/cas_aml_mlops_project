# Design

## Context

`add-presentation-evidence` (consumed, read-only here) provides `presentation/manifest.json` (schema_version 1), `presentation/evidence/summary.json`, thirteen chart SVGs (fixed `viewBox 0 0 960 540`, font-size at least 20 units, `min_render_mm: 160`, work-log element set), four reused `docs/*.drawio.svg` diagrams, nine coordinator-owned screenshots (possibly `pending`), the ZHAW logo and a null date with a visible placeholder. `scripts/build_work_log.py` is the precedent: standalone offline script, `--check`, tests load it by path, and it already contains the SVG allowlist validator and draw.io sanitizer. This change turns that material into the four-page report. Accepted user decisions in the shared context are binding: plain HTML/CSS, no JavaScript libraries, nothing vendored, no network at viewing time, works from `file://`, generated HTML in the Git-ignored `report/`, honest framing, user-authored motivation/interpretation/takeaways, no invented numbers.

## Goals / Non-Goals

**Goals:** exactly four printed A4 pages by construction and by measurement; every number from `summary.json`; every figure by manifest id with manifest caption and alt; visible placeholders (user slots, date, pending screenshots); screen navigation that vanishes in print; offline deterministic checks that run in CI.

**Non-Goals:** drafting the user's motivation, interpretation or takeaways; new evidence, charts or experiments; changes to `src/`, the work log, or the evidence change's interface; a JavaScript framework or any dependency; hosting; a CI browser job.

## Decisions

### 1. One file, four fixed sections (alternative rejected: four files)

`report/presentation_report.html` is a single self-contained file: stylesheet, SVGs, logo and screenshots inlined (SVG as markup, JPG/PNG as `data:` URIs), so it can be handed in or moved and still opens from `file://` with no network. Four files (one per page) were rejected: printing needs one PDF, four print jobs would have to be merged by hand, and cross-page figure numbering and navigation would span files. The name `presentation_report.html` keeps `report/index.html` (the work log from `build_work_log.py`) untouched; the builder writes only its own file and never cleans the directory.

Structure:

```html
<nav class="screen-only">Page 1 .. Page 4 (anchor links)</nav>
<main>
  <section class="page" id="page-1">header | content | footer "n / 4"</section> ... id="page-4"
</main>
```

Print CSS:

```css
@page { size: A4; margin: 0 }
.page { box-sizing: border-box; width: 210mm; height: 296mm; padding: 12mm 14mm;
        overflow: hidden; break-after: page; break-inside: avoid; }
.page:last-child { break-after: auto }
.screen-only { display: none !important }  /* inside @media print */
body { -webkit-print-color-adjust: exact; print-color-adjust: exact }
```

The page box is 296 mm, not 297 mm: a box exactly as tall as the sheet can spill a sub-pixel onto a fifth, blank page in Chromium and Firefox, and a one-millimetre margin removes that failure without any visible difference. `overflow: hidden` makes every page a hard box, so a too-long page loses content rather than creating a fifth page. That would hide the problem from a page-count check alone, which is why overflow detection is a separate measurement (decision 4) and why a page count of four is necessary but never sufficient. On screen the sections render as stacked sheets (max width 210 mm, shadow, centred); on narrow screens the sheet scrolls horizontally rather than reflowing, so the screen layout stays the print layout.

### 2. Sources, template directives, and what is committed

```
presentation/report/template.html   committed; hand-written four-page skeleton and prose
presentation/report/report.css      committed; screen + print rules
presentation/report/user_text.toml  committed; the user's words (slots: motivation, interpretation, takeaways)
scripts/build_report.py             build | check | measure [--pdf PATH]
tests/test_presentation_report.py, tests/fixtures/presentation_report/
docs/presentation_report.md         build, print and check instructions
report/presentation_report.html     generated, Git-ignored (spec line 175; `/report/` is already ignored)
report/presentation_report.pdf      optional, generated by `measure --pdf`, Git-ignored
```

The template is plain HTML with a small, closed set of directives resolved by the builder (a missing id, key or slot is a build error, never an empty string):

| Directive | Resolves to |
| --- | --- |
| `{{val:comparison.primary.baseline.successes}}` and a format suffix such as `\|ratio` | a value read from `summary.json` by dotted path; formats are `int`, `ratio` (`27/30`), `pct`, `chf4`, `id`, nothing else |
| `{{fig:ID}}` | the manifest figure or diagram (inline SVG sanitized by the work-log validator), its `Figure N` label and manifest caption, with the manifest `alt` as the SVG `<title>` fallback if absent |
| `{{shot:ID}}` | the screenshot as `<img>` with manifest alt and caption when `status` is `present` and the file exists; otherwise a visible dashed box "Screenshot pending (owner: coordinator): <shows>" |
| `{{ref:ID}}` | the text `Figure N` for the same numbering, so a cross-reference cannot drift from the figure |
| `{{logo}}` | the manifest `zhaw-logo` asset inlined as a `data:` URI after its recorded SHA-256 is re-verified |
| `{{title:author\|course\|date\|headline}}` | manifest title block; a null date renders the manifest `date_placeholder` in a visible highlighted box |
| `{{user:motivation}}` etc. | the text of `user_text.toml`, HTML-escaped, paragraphs split on blank lines; when empty, a visible highlighted placeholder box with the slot name and the file to edit |
| `{{limits}}` | the limits list and the non-claim from `summary.limits`, each text taken from its recorded quote |
| `{{evidence_table}}` | run IDs, bundle digests (short form plus full in a `<code>` title), prompt hashes, MLflow run IDs, completeness, from `summary.provenance.runs` |

Prose in the template is factual description from repo documents (what the sandbox, ledger and bundles do) and contains no digits except through directives; page numbers and `Figure N` are generated. An offline test strips directives and comments and fails on any remaining digit sequence that is not on a short, reviewed allowlist (for example the words "four" are spelled out and `CHF` amounts come only through `{{val:...}}`), so a typed number cannot slip in. A second test fails if the words "improvement" or "breakthrough" occur in the output anywhere except inside the summary's quoted non-claim text. This is the same discipline the evidence change uses for charts, applied to prose.

Why a hand-written template with a closed directive set rather than a Markdown pipeline: layout of four fixed boxes, figure placement and per-page budgets are layout decisions that Markdown cannot express, and the directive set is small enough to test exhaustively. The builder is expected to be about 400 lines of standard-library Python plus `scripts/build_work_log.py` loaded by path for `validate_svg` and `sanitize_drawio_svg` (a dependency on a script, not on `src/`).

Rejected: building from the existing `report/index.html`; two separate sources of numbers; client-side JavaScript to fill values (the page must work printed from a viewer with scripting disabled).

### 3. Content plan per page (structure mirrors the approved deck outline)

| Page | Content | Sources |
| --- | --- | --- |
| 1 | Header with logo, title, author, course, date; motivation USER SLOT; problem statement (unsafe candidate code, flaky or hidden cost, irreproducible results, small-sample claims) with the headline sentence; one-paragraph roadmap | manifest title, `user_text.toml`, factual prose |
| 2 | Approach: architecture figure (`architecture-logical`) and run-flow figure (`run-flow-sequence` or `-activity`, chosen after seeing both at print width); scoring integrity (sandbox, trust boundary, hidden checks, what the isolation probes cover, from `docs/threat_model.md`); reproducibility (bundles, digests, grading replay, completeness check, MLflow traces, one screenshot figure when present); budget-safe paid calls (reserve-before-send, ceiling, total spent as quoted in `summary.ledger_quotes`); experiment design (tasks, trials, one prompt sentence changed) | diagrams, `summary.provenance`, `summary.ledger_quotes`, reviewed docs |
| 3 | Results and statistics, one block per chart set (a outcome comparison, b failure labels plus both trace stories, c efficiency and cost, d engineering: tests, CI, archived changes), each figure with manifest caption and a one-sentence reading that only restates the plotted values | charts by id, `summary.comparison/efficiency/stories/engineering` |
| 4 | Limits (all seven, quoted) and the non-claim; lessons learned (MLflow big-integer bug, smoke forcing, from `docs/progress.md` and `docs/smoke_evidence.md`); conclusions/takeaways USER SLOT (interpretation); references/evidence section; footer with build provenance (summary commit and script hash) | `summary.limits`, `user_text.toml`, `evidence_table`, repo document links |

The references/evidence section on page 4 gives, as visible text and not only as links (links are dead on paper): the two comparison run IDs and the forced-pass smoke run ID with bundle digests and MLflow run IDs, and the repository paths of the documents the report relies on (`docs/prompt_comparison.md`, `docs/comparison_evidence.md`, `docs/smoke_evidence.md`, `docs/ci_evidence.md`, `docs/threat_model.md`, `docs/demo.md`, `docs/evaluation_design_guide.md`, `docs/progress.md`). On screen each is also a relative link (`../docs/...`, resolved from `report/`, valid in the checkout). The link to the work log (`index.html`) and to the recorded demo player (`demo.html`) are relative sibling links shown on screen with their path printed; a missing sibling is a non-fatal builder note (those files are generated and Git-ignored), never an error, and the link text says which script builds it.

Figure budget (see open question 1, which this table depends on): the report embeds the following figures and diagrams, in this order, numbered `Figure 1..N` by appearance: architecture, run-flow, (screenshot, optional), then on page 3 `outcome-overview`, `outcome-by-category`, `failure-labels`, `story-lists-02`, `story-strings-01`, `efficiency-calls`, `cost-charged-reserved`, `engineering-tests`. The remaining charts (`outcome-by-task`, `efficiency-tokens`, `efficiency-latency`, `engineering-ci`, `engineering-changes`) stay in the deck and in the evidence directory; the report covers each of the four sets with at least one chart and gives the omitted values as a compact HTML table taken from `summary.json` (for example the CI runs and archived changes of set d, and the latency totals with the evidence change's caption wording "measured once, different times, no attribution"). The selection is a list in the template, so changing it is an edit, not code.

### 4. Enforcing and checking exactly four pages

Two layers, because "four sections exist" is trivially true and "no section clips content" is the real risk.

1. **Offline static checks (CI, no browser)**: `build_report.py check` builds in memory and asserts: exactly four `section.page` with ids `page-1..4`; no `<script>`, no event-handler attribute, no external `http(s)`/`//` reference, no `url(` in CSS beyond `data:`; every directive resolved; unique ids after inlining (each inlined SVG has its ids prefixed with its figure id so two draw.io diagrams cannot collide); figure numbers contiguous in document order; every `Figure N` reference resolves; the print CSS contains `@page` A4, `break-after: page` on `.page`, the 296 mm box and the `screen-only` hide rule (a regression test against an accidental edit); a per-page **content budget** (a coarse static guard: number of embedded figures, and visible character count after tag stripping, each compared with a per-page limit stored in `report.css`-adjacent constants in the script, calibrated once against the browser measurement and recorded in the design notes of `docs/presentation_report.md`) so an obviously too-long page is caught without Chrome; the placeholder/slot report (below); the claims and digits lint of decision 2. These are deterministic and run in the existing CI `offline` group, which has no browser.
2. **Browser measurement (local, recorded by hand)**: `build_report.py measure` locates a Chromium-family browser (`--browser PATH`, else `$REPORT_BROWSER`, else known macOS/Linux paths; absent browser exits with a distinct code 3 and the message "SKIPPED: no browser", never a silent pass) and does two things on a throwaway copy of the built page in a temporary directory: (a) loads a copy with a small measuring script injected (the shipped report has no JavaScript) via headless `--dump-dom` with a virtual-time budget; the script writes, per page, `scrollHeight`, `clientHeight` and the lowest bottom edge of any child, and the builder fails if any page has `scrollHeight > clientHeight` (clipped content, because of `overflow: hidden`) and warns if the used height exceeds 94% (headroom for another font stack or browser); (b) prints to PDF (`--print-to-pdf --no-pdf-header-footer`, A4 from `@page`) and counts pages from the PDF page tree using the standard library (`/Type /Page` objects, cross-checked with the root `/Count`), and fails unless the count is four. It prints a table (page, used mm, available mm, percent) so the result can be pasted into `docs/progress.md` with the browser version. `measure --pdf PATH` keeps the PDF the user can hand in; Git-ignored.

Why no browser job in CI: the page uses the system font stack on purpose (nothing vendored, no web fonts), so pagination can differ across runners; a CI browser check would be flaky evidence or would pin a font we deliberately do not ship. The headroom rule plus the local measurement is the honest evidence; the static budget is the always-on guard. Why not per-page HTML files with page counting per file: it would still need the same overflow measurement, and it multiplies print steps.

Manual print recipe (also in `docs/presentation_report.md`): open the file, print, destination "Save as PDF", paper A4, margins None, background graphics on, headers and footers off; the expected result is four pages with no navigation bar.

### 5. Screen navigation that disappears in print

A `<nav class="screen-only">` with anchors `#page-1..#page-4`, sticky at the top, with the current-page highlight done by `:target` (no JavaScript), plus per-page "previous | next" links in each page footer inside a `screen-only` span. Both are hidden by `@media print`; a test asserts the hide rule and that no navigation text appears in the print-visible DOM of a build by checking the class on every nav element. The footer page counter "n / 4" is generated and stays in print.

### 6. User slots, date, pending items

`presentation/report/user_text.toml` holds `motivation`, `interpretation`, `takeaways` as multi-line strings, empty by default; the file header explains that these are the user's words and nobody else drafts them. Empty slots render as unmistakable boxes ("YOUR TEXT HERE: why evaluating coding agents matters to you; edit presentation/report/user_text.toml") in a high-contrast style that also prints; filled slots render the text in the normal body style with no marker. `build_report.py build --require-user-text` (the release build) fails while any slot, the date, or any screenshot used by the report is unfilled; the default build succeeds and lists them in a "placeholders" summary line. `check` reports the same counts. A slot box has a reserved minimum and maximum height so an empty slot and a filled slot occupy the same space; a filled slot longer than the maximum fails `check` with the slot name and the allowed length, so the user's text cannot silently break the four-page guarantee. Tools never choose a date.

### 7. Figure numbering, captions, provenance

The builder assigns `Figure N` in order of first appearance across diagrams, charts and screenshots; captions and alt text come only from the manifest; the builder never composes a caption. The evidence change's chart captions already state the limits and the single-measurement note for latency and cost; the report must show the caption unchanged. A source footnote under each chart lists the manifest `source_keys` in small type, so each plotted number traces to `summary.json`. Because the manifest has no figure number, numbering is a report concern (open question 3 records that the deck may number differently).

### 8. Shared and pre-existing files; edits to list for merge

New files only, plus small additive edits, which the coordinator merges with the deck and evidence changes:

- `README.md`: one row/line for the report build and check commands.
- `docs/progress.md`: a section recording the measurement and placeholders status once run.
- `docs/work_log.toml`: register `docs/presentation_report.md` as a document section.
- `.github/workflows/ci.yml`: one step in the `offline` job: `.venv/bin/python scripts/build_report.py check`.

`scripts/build_work_log.py` is read (loaded by path), not modified; `report/index.html` is not rebuilt or touched.

### 9. Tests (offline, deterministic, no browser)

Fixtures hold a tiny `summary.json` and `manifest.json`, two small SVG charts, a stub diagram, a 1x1 PNG and JPG and a template exercising every directive. Tests cover: directive resolution and failure on a missing id, key or slot; number formatting; HTML escaping of the user text and of summary strings; sanitizer rejection of a script-bearing SVG; id uniqueness after inlining; figure numbering and `{{ref:}}` agreement; pending screenshot rendering; null-date placeholder; empty and filled slots, over-long slot failure, `--require-user-text` failure and success; the digits lint and the claims lint (including a template edit that adds a bare number); structural checks (four pages, print CSS rules, no script, no external reference); navigation hidden in print; deterministic output (two builds identical, no timestamp); a build with no manifest screenshot files present; the page-count helper on two hand-made minimal PDFs (three and four pages); the measure-result parser on canned measurement output (clip detected, headroom warning); and that no script reads the ledger or opens anything outside the repository. The browser path itself is exercised by hand and recorded; the test for it skips cleanly only when no browser is found and says so.

## Risks / Trade-offs

- **Chart density versus legibility (open question 1).** The charts were fixed by the evidence change at `min_render_mm: 160` (about 9.4 pt text); four pages with 13 charts at 160 mm cannot fit (a 160 mm chart is 90 mm tall, three fit on one page). The proposed selection places eight charts in a two-column grid about 91 mm wide, where 20 units is about 6 pt. That is legible but below the evidence interface's own minimum.
- Pagination depends on the viewer's font stack → headroom threshold, 296 mm boxes, local measurement recorded with browser version, no claim for other browsers.
- User text length changes layout → fixed slot box and a length limit enforced by `check`.
- `overflow: hidden` can hide content in a viewer with different fonts → the measurement is the detector; documented in `docs/presentation_report.md`.
- Draw.io diagrams sanitized for the work log may lose detail at print width → judged in the implementation phase by the coordinator in print preview, with the text twins in `docs/architecture_*.md` as the accessible fallback (referenced, not duplicated).
- Shared-file edits collide with the other two changes → additive, listed above.

## Migration Plan

Implement on a branch from `main` after `add-presentation-evidence` merges: builder and template with fixtures, static checks, CSS and page budgets, browser measurement, docs and CI wiring, real build and measurement. Rollback is deleting `presentation/report/`, `scripts/build_report.py`, the test, the doc and the four small edits; nothing under `src/` changes and `report/index.html` is unaffected.

## Open questions for the coordinator

This proposal assumes 6 pt.
2. **Design facts not in `summary.json`.** Experiment-design numbers (tasks, trials, the budget ceiling and checkpoint) and the probe categories are not among the summary sections listed in the evidence design (`ledger_quotes` is quoted from `docs/prompt_comparison.md`). Preferred: the evidence summary gains a small quoted `protocol` section; fallback: this change adds its own `(file, quote, extract)` table using the same verification.
3. **Shared user-text file.** Should deck and report read one committed file for motivation and takeaways (the user writes once) or separate files? This proposal uses `presentation/report/user_text.toml` and can be pointed at a shared path.
4. **Work log link.** Confirm the report links to `report/index.html` and `report/demo.html` as printed paths plus screen links, with missing siblings a non-fatal note.
