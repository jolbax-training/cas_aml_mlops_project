Motivation

{{user:motivation}}

Problem statement

Scores reported for coding agents are hard to trust. Four things go wrong, and the project is built around closing each one:

  • Unsafe candidate code. The agent writes code that has to be run to be judged, and running untrusted code can reach credentials, the host or the scoring itself.
  • Flaky or hidden cost. Paid model calls add up unnoticed, and a retry loop can spend more than was planned.
  • Irreproducible results. A score without the exact code, prompt, settings and saved transcripts cannot be checked again by someone else.
  • Small-sample claims. A few trials per task cannot tell a real difference from run-to-run noise, yet they are often reported as if they could.

The headline of this work is therefore a trustworthy, reproducible, budget-safe evaluation pipeline for a coding agent, not a better agent.

Approach

{{fig:diagram-architecture-logical}} {{fig:diagram-run-flow-sequence}}

Scoring integrity

Each check of a candidate runs in a fresh Podman container with no network, a read-only filesystem, all capabilities dropped, an unprivileged user and limits on time, memory and processes. The container receives only the source, the function name and one check's arguments. Expected answers and the comparison stay on the host, so a candidate can influence the verdict only through what it returns.

Isolation probes cover the protected assets of the threat model: {{val:protocol.probe_categories.0}}; {{val:protocol.probe_categories.1}}; {{val:protocol.probe_categories.2}}; {{val:protocol.probe_categories.3}}; and {{val:protocol.probe_categories.4}}. The threat model records one accepted residual: code that walks the executor's own frames can forge a report, but a forged value is no better than a returned one because expected answers never enter the container.

Reproducibility

Every run is saved as a local bundle before any tracking happens, and a digest of the bundle is recorded. Traces can be inspected without any model API or container. Grading replay reruns saved final candidates against the retained benchmark in Podman with no model call and no credentials; it regrades, it is not a new agent trial. A completeness check confirms every planned trial was recorded ({{val:provenance.runs.baseline.completeness.recorded}} of {{val:provenance.runs.baseline.completeness.planned}} for the baseline, {{val:provenance.runs.revised.completeness.recorded}} of {{val:provenance.runs.revised.completeness.planned}} for the revised run). Agent, model and tool interactions of both runs are recorded as traces in a local MLflow service.

Budget-safe paid calls

All paid calls share one ledger. Before each request the worst-case cost is reserved; a request that would pass the ceiling is never sent. A checkpoint of CHF {{val:protocol.checkpoint_chf|chf}} lets the work continue and a ceiling of CHF {{val:protocol.ceiling_chf|chf}} stops it. The ledger total recorded after both comparison runs is CHF {{val:protocol.ledger_total_chf|chf4}}, quoted from the comparison document; the ledger itself is never read by the report tooling.

Limits, lessons and conclusions

Limits

{{limits}}

Lessons learned

  • Tracking and large integers. A few traces could not be read back from the tracking server because the model's check arguments held integers outside the range it accepts. The writer now stores such values as decimal strings and marks the span; the bundles are unchanged, and all traces of both comparison runs were re-recorded and read back.
  • Forcing the last model call in a smoke run. The unforced smoke runs never reached the final-only call because the model submitted early. A smoke-only instruction made that call reachable; a forced trace is a prompted call and says nothing about model quality.
  • Failed CI runs are history. The first CI run failed in the sandbox tests and later runs fixed signals and cleanup; the failed runs stay in the evidence ({{ref:engineering-tests-compact}}).
